Post 2 — Technical insight:
"One thing I learned building a production data pipeline:

Idempotency is non-negotiable.

Your pipeline WILL run twice sometimes. A server restarts, a DAG retries, someone triggers it manually.

If your inserts aren't idempotent you get duplicate data. Garbage in, garbage out.

Fix: PostgreSQL ON CONFLICT (ticker, trade_date) DO NOTHING

One line of SQL. Saves hours of debugging.

What's your go-to pattern for handling duplicate data?

#DataEngineering #SQL #PostgreSQL #DataQuality"

Post 3 — Lessons learned:
"30 days of building a data pipeline taught me:

1. Tests are not optional — they saved me 10x the time they took to write
2. CI/CD changes everything — knowing every push is validated removes anxiety
3. Document your decisions — ADRs forced me to think deeply about every tool choice
4. AI integration is easy — the hard part is the reliable pipeline underneath it
5. Start with idempotency — design for failure from day one
